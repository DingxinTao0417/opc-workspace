# ADR-005：Agent Harness 架构与本地大模型接入

- 状态：已接受（AI 助手 agent 架构纵切实施）
- 日期：2026-09-03
- 对应任务：[agent harness 分阶段计划](../plans/agent-harness-phases.md)
- 明确授权：用户 2026-09-03 要求设计包含 harness 核心组件的 agent 架构，支持多协议接入 LLM、支持接入本地大模型，并为后续知识库预留扩展点（知识库本轮不做）；本轮边界仅限 AI 助手与模型设置内容，不新增与其他模块的联动；开发完成后不提交代码，等用户确认
- 当前代码基线：app v0.1.0 / API v1 / SQLite schema 054 → 本纵切新增 055
- 与 ADR-004 的关系：继承全部安全边界（密钥仅 OS 安全存储、模型输出只读、语义建任务人工确认、AI 表排除导出）；本 ADR 撤销 ADR-004 中"不做本地部署模型适配"的延后决定（用户本轮明确要求接入本地大模型），并新增 harness 运行时设计

## 背景

AI 助手首个纵切（ADR-004）交付了远程 Provider 双协议流式会话。`chatAI` 管线目前是单次 LLM 调用的内联实现：加载 Provider/密钥 → 并发闸门 → 持久化用户消息 → SSE 流式转发 → 收尾。缺少可演进的运行时结构：没有运行循环抽象、没有工具注册与执行机制、没有上下文组装扩展点。用户要求补齐 agent 架构（harness 核心组件），并接入本地大模型（此前被显式延后），同时为知识库检索预留接入位。

命名边界：本 ADR 的 "harness" 指 AI 助手的模型运行时。既有 `agent_adapters` 域（本地 Agent Runtime / 自动化 Adapter，另有 ADR 约束）是不同领域，本 ADR 不改动它。

## 决策

### 1. Harness 核心组件（Sidecar `internal/harness`）

运行时由以下组件构成，全部为 Sidecar 代码所有，配置与提示词不进数据库：

- **LLMClient 接口**：harness 只依赖接口（流式回调 + 返回结构化回合结果）。`modelclient` 提供真实实现（包装既有 `StreamChat`），测试注入假实现。
- **Run 循环**：`harness.Run` 按"调用 LLM → 若有工具调用则执行并把结果回填 → 继续下一轮"迭代，直到产出最终回复或触发预算；本轮生产环境没有任何注册工具，循环退化为单次调用，行为与现有管线一致（SSE 契约 `opc-ai-sse-v1` 不变）。
- **Tool / Registry / Executor**：工具为命名接口（名称、摘要、执行），注册表唯一性校验 + 显式 allowlist；执行器带单工具超时、结果字节上限、panic 恢复。工具机制本轮仅以测试验证（假工具），不向生产注册任何工具——ADR-004"禁止工具调用/bash"对本轮交付物仍然成立，工具的实际启用（含知识库检索工具）必须在后续纵切中逐个评审授权。
- **上下文来源扩展点（设计预留）**：未来知识库检索应通过受控来源接口把带来源标识的片段注入提示词，并使用独立字节预算。本纵切代码未创建名为 `ContextSource` 的接口；现有实现只有会话窗口与长期记忆参数，后续接入时仍需落地接口和测试，不能把设计位视为当前能力。
- **预算**：沿用并集中于 harness——首 token 90s / 总时长 10min / 响应 1 MiB / 提示 64 KiB，另加最大轮数与工具结果总量上限。

`chatAI` 处理器改为经由 harness 执行，持久化、SSE、并发闸门、启动恢复逻辑保持不变。

### 2. 本地大模型接入（Provider `kind`）

- `ai_providers` 新增加法列 `kind`（`remote` | `local`，默认 `remote`，迁移 055）。
- 本地 Provider = **OpenAI 兼容端点 + `openai_chat` 协议**：Ollama、LM Studio、llama.cpp server、vLLM 等主流本地推理服务都暴露 OpenAI 兼容 API，无需新协议映射器，直接复用现有流式适配器与健康探测（`/models`）。
- **无密钥**：本地 Provider 不存储、不要求 API key。聊天跳过密钥库读取；对本地 Provider 调用密钥端点返回 409 `AI_KEY_NOT_ALLOWED`。
- **回环防护**：`kind=local` 强制 URL 解析后的 scheme 为 `http` 且 hostname 精确等于 `127.0.0.1` 或 `localhost`，拒绝 userinfo/query/fragment（SQL CHECK 保持基础白名单，Go 做严格校验）；Go 默认 HTTP 客户端对回环地址不走代理，本地流量不出本机。
- 远程 Provider 行为完全不变（仍要求密钥）。

### 3. 多协议接入

- 保留 `openai_chat` / `anthropic_messages` 适配器注册表；协议扩展路径固化为：新增协议常量 + 请求构造 + 流式解码 + 健康探测路径四处代码。新增协议适配器不在本轮范围。

### 4. 知识库扩展点（仅设计，本轮不实现）

- **注入式上下文**：知识库纵切需新增受控上下文来源接口，在 Run 前把检索片段注入提示词上下文，独立字节预算，带来源标识；当前代码尚无该接口或检索实现。
- **工具式检索**：知识库也可作为注册表中的检索工具（模型按需调用），启用时同样受人工授权评审约束。
- **外发边界**：知识库片段只随用户发起的那次 Run 的提示词外发；不进导出面、不进日志。

### 5. 边界（本轮）

- 仅实现 AI 助手页与模型设置中的内容；不新增与其他模块的联动（语义建任务建议卡片维持现状）。
- 知识库、更多协议适配器、生产工具、执行时间线 UI 数据源（工具调用/命令输出）均不做。
- 开发完成后**不提交代码**，由用户验证后再决定提交。

## 被拒方案

- 原生 Ollama 协议适配器：OpenAI 兼容层已覆盖，多维护一套映射器无收益。
- harness 放前端（WebView 直连模型）：破坏密钥与外发边界（ADR-004 已拒绝 WebView 直达 provider）。
- 本地 Provider 复用密钥机制（允许存 key）：本地服务不需要密钥，保留入口徒增误配置面。
- 本轮直接启用工具或执行时间线：违反 ADR-004 边界与用户"不做联动"的边界；工具机制先以测试验证。
- 新增 `ai_runs`/`ai_run_steps` 表：本轮循环退化为单次调用，`ai_generations` 已覆盖持久化与恢复；运行步骤表推迟到工具纵切随真实数据一起设计。

## 验收闸门

- harness 单元测试（假 LLM/假工具：单轮直通、多轮工具循环、预算、取消、注册表唯一性、执行器超时/panic/超限）+ 既有 `ai_chat_test.go` 全绿（SSE 契约未变）。
- 本地 Provider：无密钥创建→健康→流式聊天全链路 Go 测试；密钥端点 409；远程行为回归不变；迁移 055 加法、业务导入兼容契约覆盖 schema 55。
- Web：类型检查 + vitest 全绿（设置表单 kind、本地徽标、既有测试不回归）。
- 真机联调（Ollama/LM Studio）需用户本机环境，门禁全程以 httptest 模拟；验证步骤写入模块文档。

## 影响

- 迁移 055（加法列，默认 remote，无破坏性）；业务导入兼容边缘扩展到 schema 55。
- `chatAI` 管线重构为经由 harness，外部 SSE 契约与持久化行为不变。
- 后续工具纵切（知识库检索、只读数据工具）获得现成的注册/执行/预算机制；bash 类工具仍需独立 ADR。
