# ADR-007：会话上下文压缩与记忆工具

- 状态：已接受（设计固化；实施按 G 阶段推进，待用户确认启动）
- 日期：2026-09-03
- 对应任务：[分阶段实施计划](../plans/context-memory-phases.md)（G1–G5）
- 明确授权：用户 2026-09-03 讨论确定长程上下文管理方向——摘要 + 关键信息提取 + 滚动窗口，并综合外部存储与工具调用；用户认可结构化快照设计并授权将设计固化于本 ADR
- 与 ADR-004/005/006 的关系：继承全部安全边界；本 ADR 规划的 G3 阶段将实现两协议 tool_call 解析并注册**首个真实工具（记忆工具）**——这是对 ADR-004"禁止工具调用"的首次正式突破，仅限本 ADR 列明的三个记忆工具，其余工具仍须逐个评审
- 当前代码基线：app v0.1.0 / API v1 / SQLite schema 056 → 本纵切新增 057

## 背景

当前长程上下文只有两层：会话历史窗口（64 KiB 字节预算内从最新往回硬截断，无摘要）与用户确认的长期记忆（`ai_memories` ≤8 KiB 注入）。存在四个缺口：

1. `chatHistory` 的 `ORDER BY created_at ASC ... LIMIT 200` 使超过 200 条消息的会话取到**最老的 200 条**——最新上下文反而丢失（方向性 bug）。
2. 被截断的早期对话直接消失，长会话中"前情"不可恢复。
3. 历史消息中的建议块（`[opc:task]`/`[opc:memory]`）原样进入上下文，白占预算。
4. 模型没有任何主动读取/记录工作状态的途径（工具机制存在但生产零工具）。

## 决策

### 1. 分层上下文栈（组装器 = 纯函数）

每次生成的提示词由组装器按五段独立预算拼装：

```
系统提示（代码所有，固定）
长期记忆 ≤8 KiB（ai_memories，已确认偏好）
前情摘要 ≤4 KiB（最新快照的 summary）
关键事实 ≤4 KiB（最新快照的结构化事实：决策/约束/实体/未决问题/进度）
滚动窗口（剩余预算，按 turn 边界从最新往回装载）
```

- 组装器是纯函数，预算切分、turn 边界截断、块剥离全部可单测；修复 200 条取反 bug。
- 历史消息发送前剥离 `[opc:task]`/`[opc:memory]`/`[opc:selfcheck]` 块（UI 语义，不是上下文）。
- 预算仍为字节（首版诚实标注），token 精算后置。

### 2. 存储层：append-only 压缩快照表（SQLite，非磁盘文件）

- 迁移 057：`ai_memory_entries`（id、session_id、kind、content、tags、origin、status、source_message_id、created_at、updated_at），**只插入不更新**；撤销/演进以追加新行 + 旧行标记 superseded 表达。
- 每个压缩周期产出一行**快照**（summary + 结构化事实集）；新快照 supersedes 旧快照，旧行保留供审计与回放；读取永远只取最新 active 快照。
- 快照的合并/去重/冲突覆盖由压缩时模型一次完成（输入含旧快照），存储层无 fold 逻辑。
- 会话级事实随会话删除；`ai_*` 表照旧排除业务导出、覆盖于一致性备份。

### 3. 压缩管线：Run 后异步，失败静默降级

- 触发：Run 收尾后，窗口外未压缩字节 > 16 KiB 且该会话无压缩在飞（复用 registry 互斥模式）→ 后台 goroutine。
- 单次 LLM 调用（同 provider、harness 预算、静默）：输入 = 上一快照 + 本批滚出窗口的消息（单批 ≤32 KiB，压多少水位线推多少）；输出 = 严格 JSON `{summary, facts[]}`；提示词铁律"只压缩不推断，旧快照中仍相关事实必须全部延续"。
- 落库与水位线推进在同一事务；成功记 `ai_session_compacted` 脱敏事件（仅条数/字节数）。
- 失败不重试于当轮、不阻塞聊天：水位线原地，下次触发再试；聊天始终按硬截断兜底。

### 4. 工具层（G3/G4）：首个真实工具 = 记忆工具，push/pull 混合

- G3 实现两协议 tool_call 流式解析与 harness 下发/聚合（请求侧工具定义、流式增量累积、多工具调用）。
- G4 注册三个工具，全部走 allowlist 与既有预算：
  - `memory_search`：按关键词/tags 检索 active 条目与历史消息（首版确定性检索，无向量依赖）；
  - `memory_write`：agent **自发**写会话级事实（自动、随会话亡、无需确认）；
  - `memory_propose`：跨会话持久记忆只能**提议**（pending），仍经用户确认卡片落地——ADR-006 人工门禁不松。
- push（摘要+事实注入）与 pull（工具检索）互为兜底：本地小模型工具调用可靠性参差，注入层保底。

### 5. 边界（不变项）

- 压缩产物是模型输出 → 不可信 → 只进上下文，不落业务事实，不触发任务/客户等模块。
- 外发面无新增数据类：摘要与事实是用户自己会话内容的衍生物。
- 持久记忆确认门禁、模型输出不可信预览、AI 表导出排除均不变。

## 被拒方案

- 磁盘 JSONL 文件作为存储介质：备份/恢复/导出排除体系全部围绕 SQLite 建立，第二存储介质破坏一致性恢复故事；采纳其"append-only 行式 JSON 记录"的结构精神，介质留在 SQLite（用户 2026-09-03 讨论后同意抛开文件方案）。
- 条目级增量合并（每条事实一行、LLM 逐条更新）：fold 逻辑复杂且误差累积；改为快照制，合并交给压缩时模型单次完成。
- 纯 pull 记忆（只靠工具检索、不注入）：本地小模型工具调用可靠性不足时会静默失效；注入保底 + 检索增强。
- 向量/嵌入检索先行：依赖知识库模块（AI6），首版用确定性关键词/tags 检索。
- token 级预算先行：中文场景字节预算已够用且可测，tokenizer 精算后置。

## 验收闸门

- 组装器纯函数测试：五段预算、turn 边界、200-bug 回归、块剥离。
- 压缩管线：假 LLM 验证快照延续与水位线推进、失败降级、并发互斥、事件脱敏；注入后 mock 上游断言各段存在且预算不超。
- 工具协议：两协议 tool_call 流式解析单测（mock 上游增量帧）、harness 聚合、预算约束。
- 记忆工具：search/write/propose 行为与边界测试（propose 不经确认绝不持久化）。
- 全量回归绿色；不提交代码，等用户确认。
