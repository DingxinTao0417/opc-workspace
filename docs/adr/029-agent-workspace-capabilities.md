# ADR-029：智能体与工作台的显式能力桥接

2026-09-23 H5-G49 决定：显式授予 `workspace_ui` 的单消息双面板请求可包含可选 `split_ratio`，值域 0.25–0.75，表示主面板初始宽度比例。缺少 companion 或值越界时拒绝整项请求；旧无比例请求兼容。前端只在精确面板配对成功后应用，后续仍由用户调整；该字段是显示偏好，不扩大数据读取或执行能力，不新增授权、持久化或 API/schema。详见 [H5-G49](../modules/ai-assistant.md#智能体请求工作区的初始分栏比例h5-g492026-09-23)。

2026-09-23 H5-G48 决定：右侧 Agent 工作区的双标签分隔条应支持本地比例调整，范围 25%–75%；分隔条同时支持指针拖动、方向键（Shift 加速）、Home/End 和双击均分。单面板隐藏控制，调整不改变主次标签身份、外层聊天/工作区比例或工具内容边界；不持久化，无 API/schema/scope 变化。见 [AI 助手 H5-G48](../modules/ai-assistant.md#智能体工作区双面板比例调整h5-g482026-09-23)。

2026-09-23 H5-G47 决定：AI 单文件修改提议的右侧工作区预览必须是同一 WebView 内存状态的只读镜像，通过精确 `proposalId` 绑定具体提议。只有完整生成后由用户点击左侧卡片显式打开；旧标签不得切换显示新提议，状态清除后展示不可用。复核、批准、写入与恢复仅保留左侧原生审查卡一条路径；不重新读文件、不调用模型、不恢复历史、不增加模型工具枚举、scope、API/schema 或文件能力。详见 [H5-G47](../modules/ai-assistant.md#ai-文件提议的右侧只读预览h5-g472026-09-23)。

2026-09-23 H5-G46 决定：把已授权 `workspace_ui` 的固定单标签打开扩展为可选双标签布局，不增加面板内容读取或执行能力。保留输入 `panel` 与单面板 `workspace_panel` SSE；只有显式提供不同闭集 `companion_panel` 才发出精确双面板事件，由主 WebView 顺序打开/激活并固定主次顺序分栏。拒绝未知/重复标签和两个 Chromium 面板；不传递 URL、路径、文件内容或命令。即使打开终端/浏览器也不代表启动或导航。布局请求按事件身份只消费一次，重挂载不会重放旧请求。无 API 路由、数据库/schema、权限或 Runner wire 变化；确定性测试覆盖工具、SSE、解析及 UI 分栏。详见 [AI 助手 H5-G46](../modules/ai-assistant.md#智能体请求双面板工作区布局h5-g462026-09-23)。

2026-09-23 H5-G39 决定：将 H5-G32 的单子会话停止扩展为父会话右侧用户选择式原子批量停止，最多四个精确子 Generation，一张确认清单对应一次确认。服务端先以只读事务重投影每个已授权的当前子轮，再在 Generation registry 与 delegation Coordinator 的统一锁顺序下预检所有活动 Worker；全部可停止才发送任何信号，防止部分取消。`202` 只表示整批本地停止请求已接受，仍需重读权威终态；没有自动级联、模型 interrupt、Task Agent Run 控制或远端撤回语义，不改变 schema079、scope 或 Runner wire。见 [AI 助手 H5-G39](../modules/ai-assistant.md)。

2026-09-22 H5-G32 决定：给右侧 UI 增加受限的父方子 Generation 停止请求，不把它做成模型 `interrupt` 工具或 Agent Run 控制。每个请求都必须重新读取规范父 Session、精确子 Session、已确认 spawn/follow-up 和当前精确轮次，且由用户二次确认；已受理轮次发给 Generation 取消句柄，Coordinator 预受理轮次由同进程 worker 原子选择取消终态或既有失败终态。202 回执表示“请求已接受”，最终状态仍读数据库；也不表示已撤回远端请求/计费或工具副作用。它不级联兄弟任务，不影响 Task Agent Run。UI 投影可以包含活动/预受理轮次 ID，但模型工具投影必须移除。见 [AI 助手 H5-G32](../modules/ai-assistant.md#父子会话的显式停止请求h5-g322026-09-22部分实现)。

2026-09-22 H5-G31 决定：既有子会话的续交办只通过保存主会话的专用模型工具提议，不把 `workspace_propose` 变成通用子会话消息 API。冻结完整新指令、原委派和子最新完成轮次/版本/Provider/待审批事实，人工另行勾选；确认和单次受理均重验。新生成以 Proposal ID 防重，启动不确定或重启不重发；子会话中的写操作继续逐项审批。父侧可在本条权限重验后读取最新已确认的 follow-up 回复，也可指定精确父方授权 Generation；它不会自动并入父上下文，也不会暴露子会话自行运行的其他轮次。见 [AI 助手 H5-G31](../modules/ai-assistant.md#已有子会话续交办h5-g312026-09-22部分实现)。

2026-09-22 H5-G30 计划门禁补充：父计划不能把“子模型完成”当成“子工作已无待审批操作”。确认回执通过同一只读计数暴露有效子审批数量；大于零时阻止计划满足和自动续办，决定后才可重查解除。此阻塞不构成父会话审批权限，也不是 follow-up 执行许可。见 [AI 助手 H5-G30](../modules/ai-assistant.md#子任务待审批阻塞可见性h5-g302026-09-22)。

2026-09-22 H5-G30 决定：子会话模型生成完成但仍有未决定操作时，父侧不能仅凭 `completed` 推断交付可继续。复用已确认父子关系和子 Generation/Proposal 账本，按与原审批卡一致的 24 小时边界返回待确认数量；不把子审批正文或确认能力转交父会话。follow-up 的提议与接受点都重新核验该阻塞，而不信任列表快照。见 [AI 助手 H5-G30](../modules/ai-assistant.md#子任务待审批阻塞可见性h5-g302026-09-22)。

2026-09-22 H5-G29/H5-G31 决定：子任务长回复分页显式返回所选父方授权 Generation ID 与完整正文摘要；非零偏移续页必须同时带回 `generation_id` 和预期摘要，服务端在权限和消息一致性重验后拒绝跨版本拼接。摘要只用于结果一致性，不充当业务证明或新的权限凭证；`list/wait` 保持元数据最小化，不携带分页字段。见 [AI 助手 H5-G29](../modules/ai-assistant.md#子任务回复分页的一致性绑定h5-g292026-09-22)。

2026-09-22 H5-G28 决定：在既有只读子会话工具上提供最长 15 秒的精确终态等待，不另造可写消息邮箱或授权通道。等待期间不占用跨调用的 SQLite 事务，每次重新校验已确认父子身份；仅返回状态，回复正文仍独立要求原 scope/知识源/Provider 重验。子终态后的无载荷通知只加速既有租约的事实重查，不能成为新模型运行或审批许可；3 秒扫描仍兜底。见 [AI 助手 H5-G28](../modules/ai-assistant.md#子任务终态等待与计划唤醒h5-g282026-09-22)。

2026-09-22 H5-G27 决定：父智能体可用本条新授权按需读取已确认子任务状态及原委派或本父会话已确认的 follow-up 回复，但不把子会话历史并入父上下文。结果工具绑定服务端当前父会话，验证不可变委派/follow-up Proposal 与所选 Generation，再要求当前 grant 覆盖该轮 scope、同 Provider/配置版本与知识来源版本；逐份文件能力不跨会话复用。不能读取子会话自行运行的其他轮次。返回只含有界、标记不可信的 assistant 正文，不能成为工作台事实、批准或执行权限。见 [AI 助手 H5-G27](../modules/ai-assistant.md#父智能体读取子任务进展与首轮回复h5-g272026-09-22)。

2026-09-22 H5-G26 决定：父子 AI 会话关系由已确认委派的不可变 Proposal、冻结预览及子 Generation 投影，不新增第二套可修改的关系表。只读 API 对身份/范围/一层四子的历史约束失败关闭，仅公开导航所需元数据；缺失子会话不自动重建。右侧会话树与 Task Agent Run 账本并列但不混淆，导航本身不构成 send/wait/interrupt、取消级联或授权继承；后续 H5-G32 另加用户确认的单个活动子轮停止请求。见 [AI 助手 H5-G26](../modules/ai-assistant.md#父子会话的只读导航与状态h5-g262026-09-22)。

2026-09-22 H5-G22 决定：有界续办采用“提交后提示、数据库重读”的事件驱动优化。审批决定与 Agent Run 关键生命周期事实只有在事务和必要文件收尾成功后，才向进程内协调器写入一个可合并的无载荷唤醒；任何 Proposal/Run/正文/文件/Provider/授权身份都不进入信号。协调器继续以 SQLite 投影为唯一判定依据，并保留周期扫描兜底。该决定缩短已授权计划在人工决定和执行完成后的等待，不把事件总线变成授权或执行通道；并行阻塞、TTL/轮次/并发、冻结身份、人工确认和恢复门禁不变。见 [H5-G22](../modules/ai-assistant.md#权威事实提交后的事件驱动续办h5-g222026-09-22)。

2026-09-22 H5-F9 决定：计划级等待采用“扫描全部相关生成和同轮兄弟建议，再汇总阻塞”的方式，不把第一个阻塞原因当成全局状态。公开续办响应保留最高优先级 `reason/blocking_generation_id`，并增加仅含类别、数量和本会话 generation ID 的 `blockers`；主对话用它一次展示并打开全部回执组。不同 Task 可并行有活动 Run，同一 Task 唯一活动 Run 的数据库约束不变。该投影不暴露正文或授权，不自动确认/重试/恢复/继续，也不把精确重试用 `parent_run_id` 改造成委派关系。见 [H5-F9](../modules/local-agents.md#并行执行计划的全量等待状态h5-f92026-09-22)。

2026-09-22 H5-F8 决定：计划回执和右侧 Agent Run 详情必须把“执行事实”和“人工验收事实”连接起来，但不能合并。计划 UI 只根据已通过闭集路由校验的服务端 route 区分精确 Run 与精确 Submission；右侧精确 Run 仅在真实 `submitted + submission_id` 时显示批次入口，并附加 UI 自己持有的保存会话返回身份。`retained` 不伪装可验收，`pending` 不重跑模型。导航不自动执行、验收、继续计划或授予权限；无新 scope/API/schema/Runner wire。见 [H5-F8](../modules/local-agents.md#计划执行与人工验收的精确往返h5-f82026-09-22)。

2026-09-22 H5-F7 决定：把已登记的 Agent file/files 结果接入现有按次单文件产品入口，但不把 Runner 变成文件工具。只有用户从 Task 执行列表、执行过程抽屉或右侧“子智能体”精确详情明确选择的 `succeeded + submitted` 文件产出才在 WebView 内存形成候选；右侧详情只切换同一工作区的“文件”标签，不形成第二套写入路径。再由用户在右侧选一个现有文本目标、建立完整原生基线并核对完整差异。建立基线前及提交前精确重读来源 Run，逐项比对提交身份、attempt、契约序号和完整正文；读取失败或漂移发生在原生命令前。目标路径不进模型/Sidecar/Runner；候选不持久化、不批量执行。提交复用同一 `workspace_file_edit_apply`、Win32 审查、按次 UAC、helper 与恢复链，写入不改变 Submission/Task 验收事实。无新 scope/API/schema/Runner wire；普通开发构建只读，真实跨权限验收仍待。见 [H5-F7](../modules/local-agents.md#已提交文件产出到项目文件的人工桥接h5-f72026-09-22)。

2026-09-22 产品入口决定（当前，取代下方同日“产品未接/写入关闭”的阶段状态）：标准 Windows 桌面构建只有在编译摘要绑定的同目录 helper 通过只读核验时，可信主 WebView 才显示按次单文件确认入口；真正执行时，helper 仍须独立核验有效签名配对，不能把按钮可见性当成配对证明。AI 替换必须消费当前精确快照，v2 恢复必须消费刚冻结的审查票据；全局只允许一个规范 UUID operation，绑定 root 选择和可取消标志。网页勾选不授权 helper：父端先显示独立 Win32 完整审查，再以固定 `ShellExecuteExW/runas` 请求本次 UAC；helper 仍须重验安装配对、父进程世代/同用户/管道、磁盘事实、完整 SACL、attempt 与全部阶段。明确原生/UAC/helper 取消可形成 `cancelled`，其余异常为 unknown 且禁止重试；取消不回滚 `started` 后移动。普通开发构建、CLI、模型、Sidecar、子 WebView 和旧 v1 原地恢复均无该权限。确定性测试不执行真实 UAC；真实安装/SACL/发布签名/断电恢复仍是验收缺口。见 [当前产品边界](../modules/desktop-platform.md#绑定发行构建的按次单文件操作入口2026-09-22部分实现)。

2026-09-22 执行阶段决定：遵循 Codex 将 approval 与 run/result 分开的原则，不能把一次原生确认或权限观察写成“执行成功”。辅助端在 attempt 后以同一 operation/review/request 身份写完整 `prepared`；开始前必须以 `materialized` 绑定候选实体的身份、正文、普通元数据、可读权限与完整权限，再把完整 v2 恢复意图 CREATE_NEW、刷盘、回读到固定恢复目录，并以独立 `recovery_intent` 阶段绑定记录摘要、记录文件身份及源/候选身份。受控内核只能在仍处原期限、刚由新 AuditScope 重验 live 完整 SACL 后写一次 `started`，随后保持祖先固定，把观察句柄换成重新核验的 DELETE 句柄，并只执行无覆盖对象重命名。恢复绑定后的新候选由记录接管，错误不删除；首个移动之后不自动回滚。成功 outcome 只能绑定目标/保留对象的唯一完整终态；错误不写“失败”回执，损坏、缺失或回执失败仍按 unknown 处理且不自动重试。执行一旦开始，原批准到期不阻止记录已经发生的成功事实，但也不产生新执行权。helper bootstrap 必须来自已验签安装配对和固定父进程世代，只承载一次性管道身份/随机绑定/请求摘要；成功回执还必须是同一 operation ID 的规范编码，不能由任意 JSON 冒充。prepared、v2 intent 与 stage checksum 都不认证同用户历史，重启使用前仍须重验 live 对象；该阶段完成时尚无产品调用者，现已由上方受限 Tauri/网页入口串联，但模型仍无直接调用权。真实 UAC/SACL、安装恢复与断电验收仍待，见 [实现与边界](../modules/desktop-platform.md#辅助端完整准备与结果未知阶段内部实现未执行文件操作)。

2026-09-22 持久尝试决定：断连/重启/观察失败不意味着可重发。内部原生确认后以固定同用户目录、独占锁、操作/审查双身份及 CREATE_NEW 登记，刷盘回读后才观察完整权限；已有项不覆盖，失败不释放身份。只存最小元数据，不存正文/ACL 或持久凭据。这是合作进程间保守占用，不抵御用户删除/改写存储，不授权续跑或证明执行结果；完整意图/回执/断电与真实 UAC 尚待，见 [契约与验证](../modules/desktop-platform.md#辅助端持久尝试占用内部实现非执行回执)。

2026-09-22 恢复记录决定：辅助端不能仅相信请求摘要或父端重读。内部会话先验证同一用户的内核 SID、拒绝已有线程模拟身份，系统 Known Folder 加固定应用 ID 定位，不接受外部路径或另一账户的存储。严格共享 v2 解码后，与原请求的路径、对象、正文、元数据和可读权限逐项绑定，持有记录至完整权限观察复核结束；新替换不需要来源记录。保留 v2 字段/摘要格式，不把 checksum 当签名、防重账本或完整 SACL，也不设置记录中的 ACL。持久阶段和 started-only 执行后来已在内部补齐；跨用户提权、产品真实运行和恢复入口仍待，见 [当前实现与边界](../modules/desktop-platform.md#辅助端固定目录的恢复记录复核内部实现)。

## H5-B：Agent Run 可恢复产出登记（schema 075）

schema 075 为 `agent_runs` 增加 `output_delivery_status/error_code/submission_id/artifact_id` 及不出 API 的恢复 staging。合法状态只有：非成功 Run 的 `not_ready`、已完成模型但登记事务待恢复的 `running + pending + AGENT_OUTPUT_DELIVERY_PENDING`、带精确双 ID 的 `succeeded + submitted`，以及带稳定原因码且无双 ID 的 `succeeded + retained`。迁移先按 UTF-8 BLOB 长度修正合法旧 succeeded 的 `result_bytes`。超过 64 KiB 或无法形成合法有界结果的旧行不截断：若不可变事件与当前关系能唯一证明既有 Submission/Artifact 链，则保留 `succeeded + submitted`，只把 Run 结果副本替换为有界说明，完整 Artifact 继续是权威产出；没有唯一链的非法旧行才转为 `failed + AGENT_RESULT_TOO_LARGE/AGENT_RESULT_INVALID`。其余合法历史只凭同样的唯一证据回填 submitted；不能唯一证明的旧 succeeded 以 `AGENT_OUTPUT_DELIVERY_LEGACY` retained，避免虚构追溯。该不可逆规范化受破坏性迁移闸门和升级前回滚包保护。

finalize 在同一外层事务重新核对冻结 Task version、活动 Assignment/Actor、review policy 与 Task 状态，并复用 `task_output_commands.go` 的共享领域命令。满足前置时 Submission submitter 与 Artifact producer 都归冻结的 agent Actor，Artifact recorder/事件 Actor 为 system，Task 只进入 `waiting_review`；领域事实漂移时原子保留为 retained。数据库查询、事件或写入等瞬时故障整体回滚后先尝试持久化 pending，不能归类为身份漂移，也不能公开 succeeded 但没有 disposition。若完成事务与 pending staging 的首次写入都暂时失败，Worker 在进程存活期间以内存保留有界正文并持续退避重试；只有 staging 首次成功落库后才具备重启恢复，首次持久化前的进程退出/掉电是仍然存在的残余窗口。稳定的内部 request identity 避免后台事件写入空 `request_id`。

`POST /api/v1/agent-runs/:id/output-delivery/retry` 只恢复 pending；submitted/retained 幂等回读，not_ready 拒绝。重复、并发、启动恢复均不得重复创建 Submission/Artifact；pending 不允许取消，因为模型已完成且 staging 不能丢弃。Sidecar 启动先恢复 pending、重新 launch `queued + not_ready`，只将遗留 `running + not_ready` 置 interrupted；queued claim 遇瞬时存储故障时同一进程以有界退避自动重排，期间重新经过 maintenance/cancel/CAS 门禁，耗尽预算仍保留 queued 供重启恢复。AI action/workspace 回执仅公开安全交付状态、原因码和精确 ID，不带正文；submitted 优先指向 `/tasks/:taskId/submissions/:submissionId`，其他存续状态指向精确 Run。终态 Task 删除会级联 Run，但 Proposal 决定及结果标识继续作为历史回执；缺失实时 Run 时省略 live fact，前端显示不可导航 tombstone。无论 submitted、retained 或 recovered 都不会自动完成 Task。

全局 `GET /api/v1/agent-runs` 是 metadata-only 摘要列表，不返回 `result_text`、输入快照或隐藏 staging。工作区面板点击某一行后才调用精确 `GET /api/v1/agent-runs/:id`，正文展示、取消、整次重试和 pending 登记恢复都只依据这份精确详情；列表快照本身不能执行这些动作。

Task 删除在版本校验后拒绝任何 `queued/running` Run（包括 pending），返回 `409 TASK_HAS_ACTIVE_AGENT_RUN`；pending 必须先恢复登记，其他活动 Run 必须先取消或等待。全部 Run 终态后允许删除 Task，并按聚合外键级联 Run 历史。

该级联不改写已经 confirmed 的 `agent_run.start/cancel` Proposal：决定及 `result_id/result_version` 仍是历史回执，但 Sidecar 发现 Run 缺失时省略实时 `agent_run_result`。Web 只接受这一精确 confirmed+缺失结果形态作为 tombstone，将 route 置为空，显示“执行记录已删除/无法再读取运行状态”，不发 `getRun`、不轮询、不显示详情链接，也不把历史 confirmed 当作当前执行成功证据；其他缺字段或错配仍按非法回执处理。

## H2-E1：任务提交与验收事实（schema 73 不变）

`work+outputs` 新增 workspace_task_submissions；work/actions 单独不可读摘要/验收意见。每次请求在同一只读流程内读取 Task 版本/当前指针和对应批次；列表不读取正文，文本按 Unicode 在 SQL 内分页，产出元数据按真实 Task+Submission 双重定位。历史、无附件、child_rollup 均可见，文件无字节/路径，已删除产出仅元数据，不泄露删除原因或人员备注。工具不创建或审核提交，不修改业务版本，不启动 Agent；恢复/取消/Provider 配置身份和单次授权边界沿用现有运行时。

Task 当前指针不保证 pending_review，读取也不是接受证据。摘要/意见为用户不可信资料，显式披露可能含敏感内容；代码提示要求区分 Task 和 Submission 状态、不把未读页或文件视为已审查。读取不授予写权限，受确认提交/验收遵守下述 H2-E2 边界。参数、测试证据见 [Task 模块](../modules/tasks.md#ai-提交批次读取h2-e1源码与隔离测试已实现)。

## H2-E2：受人工确认的提交与验收（schema 73 不变）

保存会话的 `work+outputs+actions` 支持 `task.submit_output`、`task.review` 提议，模型不能提交同意或绕过 owner 验收。前者仅摘要和非文件产出，沿用 owner 代录/当前 assignee producer 归属；后者绑定精确当前 pending 批次，accept 完成并结束责任，request_changes 保留责任及历史。文件元数据不代表内容检查，用户必须人工核实并另勾选 `confirm_task_output`。

动作 64 KiB、预览 128 KiB，加载审核正文前再限制最多 20 项和 96 KiB，超限整体拒绝。完整正文/责任快照仅供人工，不返回给模型工具或历史回执。Task、责任、Actor 身份/版本及证据变化拒绝旧预览；与原生 API 共用 `task_output_commands.go`，领域写入、父链/Inbox 协调和审批同事务；原生文件 staging/commit/补偿仍由其入口持有，AI 不获任意文件权限。重复确认复用结果，模糊失败回读，前端取消迟到请求并刷新全部受影响读模型，包括 Artifact 详情。结果 ID 是 Submission、版本是 Task，H4-F 以 Task+Submission 真实身份定位该批次，返回来源对话，不把历史结果替换成最新提交。详见 [Task 模块](../modules/tasks.md#ai-提交与验收命令h2-e2源码与隔离测试已实现)。

## H4-F：提交批次核验与对话往返（schema 73 不变）

新增 Task+Submission 双重定位的只读 API 与页面，保留历史批次、当前指针与当前 Task 版本的独立语义，不回退最新批次。查询、审批卡及历史回执从真实身份生成路径；模型不能指定返回会话，主/侧消息界面附加实际来源。非法参数、跨任务、缺失及旧缓存不能冒充目标，页面刷新与切换仍读取精确身份。

批次摘要和意见仅在本地查看，Artifact 正文按需读、文件由人工点击下载，沿用既有受控目录/完整性校验，离页取消并忽略迟到结果。查看不执行提交、验收、删除或模型调用，也不恢复工具授权；可去任务详情继续处理或返回原对话。API、页面及确定性证据见 [Task 模块](../modules/tasks.md#精确批次定位与原对话往返h4-f源码与隔离测试已实现)。真实模型/桌面与完整长任务编排仍待。

## H2-F：项目笔记（schema 73 不变）

单次 work 授权开放 workspace_project_notes，列表仅元数据；正文必须绑定 Project+Note+Note version 并按 Unicode 分页，不读已删除正文或附件。保存会话 work+actions 提供 project_note.create/update/delete，完整本地人工预览与当前 Project 状态/版本重验，删除另需 confirm_project_note_delete。模型无执行/同意工具；笔记写入、Project 聚合版本 trigger、审批与审批事件共用事务，重复确认重放。原生幂等和 If-Match 不变，不添加假的项目生命周期事件。主/侧对话取消旧缓存并刷新，下一轮实际回执无正文、不继承权限。查询结果和已有笔记操作保存真实 Project+Note 身份，未确认创建因尚无 Note ID 只提供所属项目入口；精确定位由下述 H4-G 接续。字段、容量与测试见 [Project 模块](../modules/projects.md#ai-项目笔记桥接h2-f)。

## H4-I：工作台事项主动交接（schema 076 不变）

七类详情的人工入口只把 canonical 记录类型/ID 暂存到当前 Web 运行时，不携带正文、grant、Provider 或 Session，不写存储或调用模型。进入 `/ai` 后由用户决定是否追加问题、保留当前会话或先新建；主输入区和右侧 `WorkspaceChat` 都可准备同一待办卡。准备时保留文字草稿，明确清空旧 grant 与已选上下文，并重新打开范围确认。推荐范围不是授权，更不意味着只限当前记录；权限面板继续披露完整域、当前模型与外发边界。临时会话过滤持久操作范围，没有可用模型/正在生成时不消费待办；未保存编辑和在途写入阻止离开对应详情。整个交接只复用既有查询和审批链，没有新的执行捷径或长期能力。实现与验证见 [AI 助手 H4-I](../modules/ai-assistant.md#h4-i-从工作台事项进入智能体)。

## H4-G：项目笔记精确定位与对话往返（schema 73 不变）

`workspace_project_notes` 列表/详情、已有笔记审批卡及实际回执使用 `/projects/:projectId?note=:noteId`；确认创建后使用真实 `result_id`，未确认创建仍因没有记录 ID 只打开所属项目。Web 只接受 canonical Project/Note UUID、单个 `note` 和无片段的内部地址；模型不得提供 `return_session`，主/侧消息界面按实际来源会话追加。

项目详情复用 `GET /api/v1/project-notes/:id` 独立读取目标并核对响应中的 Project+Note，不依赖当前列表页、页长或删除筛选。缺失、跨项目、非法参数、读取失败和旧缓存不得降级为列表首项或其他笔记。未删除项显示最新完整正文；软删除项只显示版本、记录与删除元数据，正文保持 `null`，不从审批预览恢复。

打开、重试、关闭定位或返回原对话都不执行创建、修改、删除或模型调用，不恢复一次性 work/actions；原生写入口继续使用当前 Note 版本与既有事务。H4-G 不新增 API、数据库字段、业务副本或权限，API v1 / schema 73 不变。契约和确定性证据见 [Project 模块](../modules/projects.md#项目笔记精确定位与原对话往返h4-g源码与隔离测试已实现)。
