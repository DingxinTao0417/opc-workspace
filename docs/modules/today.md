# 今日工作台模块

> 实现状态截止：2026-08-28；当前数据库 schema v16。T-06A 已交付真实计划日期分组与完整分页，T-06B 已交付日期导航，T-06C/D 已交付按钮式及同组拖拽排序，T-06E 已交付任意日期/未排期安排与模糊写入验证，T-06F 已交付受策略约束的开始/完成/开始专注快捷操作，T-06G 已交付四个可见分组间按真实日期跨组拖拽、空精确日期/未排期落点与排序部分成功反馈，T-06H 已交付任务行编辑直达与版本化确认删除；T-11F 已把 Inbox/必需 Task 派生计数接入 Today 与 Sidebar。
>
> 版本边界：本文同时描述当前实现与目标规划；凡标注“规划”的内容均未在该基线交付。

## 定位与边界

今日工作台是应用的日常入口，负责把“今天要做什么、有什么风险、当前正在专注什么”聚合到一个页面。它是任务、专注、收件箱、项目和后续财务/客户事件的读取视图，不拥有这些模块的第二份业务状态。

- 任务状态、计划日期、排序和工时以任务/专注模块为事实源。
- 收件箱待处理数量和跟进状态从 Inbox Item 与关联任务派生。
- 项目、客户、收入和发票数据由对应模块提供；未实现前必须显示明确空态或“后续版本”，不得填充模拟业务数据。
- 今日页可以发起新建、编辑、排序、专注等操作，但写入仍必须通过各业务模块的 Sidecar API。

## 当前实现状态

当前状态为**部分完成**：真实任务、持久化 Focus Session、今日统计、本地日期任务分组、日期导航，以及精确日期/未排期计划组的按钮式排序和恢复默认已经接入；四个可见列表共享拖拽源，可在同日重排或按目标任务真实日期跨组移动，空的所选日期与未排期也能接收。每条活动任务可从行内入口明确安排任意日期、直达共享完整编辑，或在独立二次确认后按当前版本删除。todo 可快速开始，`in_progress + review_policy=none` 可快速完成，活动任务可在 Focus 空闲时直接开始绑定专注。

### 已实现

- `/today` 路由、三栏应用壳、今日标题、当前本地日期和基础统计卡。
- 通过任务列表的 `status=active`、计划日期范围与 `planned_state=unscheduled` 分组查询，逐页拉全逾期、今天、本周稍后和未排期任务；单页 100 条，但无总量静默截断。
- 日期栏支持前一天、后一天和“回到今天”；任务分组与 `/stats/today` 统一消费所选 `YYYY-MM-DD`。非当天视图把当天分组标为“所选日期”，不伪装成真实今天。
- 通过 `GET /api/v1/stats/today?date=YYYY-MM-DD&timezone=<IANA>` 读取当天任务总数、完成数、剩余数、逾期/临期数、预估/实际分钟和专注统计；旧调用可继续使用 `timezone_offset_minutes`，未指定时按 UTC。
- 展示预计时长、待完成数和逾期数；任务列表具备加载、空、错误和重试状态，统计查询具备错误与重试提示。
- 可打开新建任务弹窗；任务行状态图标只作展示，点击任务行可打开共享详情弹窗，在受控生命周期区执行开始、阻塞、解除阻塞、完成、取消或重新打开，也可编辑非状态字段或经二次确认删除。
- 今日任务分组的 `status=active` 服务端口径排除 `done` 和 `cancelled`。统计 API 的当天总数、剩余、逾期、临期和预计分钟排除 cancelled，完成数只统计 done；actual_minutes 保留历史并仍按计划日期累计。
- 任务事实层已提供真实分页、计划日期范围、稳定排序和 `PUT /api/v1/tasks/reorder`。排序命令按完整 `planned_date` 组及每项 `expected_version` 原子校验，并支持 `manual / default`；任务页与 Today 的所选精确日期/未排期组均已接入按钮式排序和恢复默认。
- Today 排序会读取目标日期组的完整 Task 集合并保留 done/cancelled 槽位，只在可见活动 Task 之间上移/下移；超过 1,000 项、集合变化、版本冲突或网络失败均不提前改变可见顺序，并显示可重试错误。保存期间禁用同组排序，成功后统一刷新 Task/Project/Today/Inbox 派生事实。
- 同一精确日期或未排期组支持从拖动手柄进行组内拖拽；前端立即以本地 ID 顺序预览，Sidecar 仍重新读取并校验完整计划组后原子写入。成功刷新后移除预览，失败或冲突时同样移除预览并恢复服务端顺序；上移/下移按钮保留为键盘与非拖拽替代入口。
- 四个可见列表通过页面级共享拖拽任务互为目标；落到任务行时以目标 Task 的真实 `planned_date` 和相对位置为准，因此逾期/本周多日期聚合不会猜测日期。所选日期和未排期提供组级末尾落点，拖动时即使目标组为空也会出现。
- 同日期拖拽重新读取该精确计划组并提交完整 ID/version 顺序。跨日期先用 batch `set_planned_date` 确认日期事实，再分别提交源/目标完整组 reorder；两次排序独立结算，任一失败会显示“任务已改期”及失败组并刷新，不用旧 UI 回写日期。
- 所有四个活动任务组都提供“安排日期”行内按钮；弹窗支持原生日期输入、所选日期、后一天和未排期。保存以单任务 `PATCH /api/v1/tasks/batch` 携带 `expected_version`，成功后刷新 Task/Project/Today/Inbox 派生事实；同日期不发请求，改期会按任务事实规则清除原 `manual_order`。
- 所有四个活动任务组复用同一套执行快捷操作。todo 只显示“开始执行”，无需验收的 in_progress 只显示“完成任务”；manual review、waiting_review、blocked 不显示可绕过规则的生命周期按钮。命令使用 Task 当前 `version` 与既有稳定幂等键，写入期间禁用其他行内写操作，失败显示服务端原因并按现有 Query 策略刷新冲突事实。
- 所有四个活动任务组提供明确的“编辑任务”和“删除任务”行内按钮。编辑只设置共享任务详情 ID，继续复用详情页的完整非状态字段校验、版本冲突草稿和受控生命周期；删除先显示不可恢复的独立确认弹窗，确认后调用既有 `DELETE /api/v1/tasks/:id?confirm=true` 并携带当前 `If-Match` 版本。成功刷新 Task/Project/Today/Inbox；版本冲突刷新事实并要求按最新内容重试，活动 Inbox 关系保护会给出解除关联指引。
- “开始专注”仅在活动 Focus Session 查询成功且为空、前端循环为 idle 时启用；创建使用已保存而非设置预览中的专注分钟/轮数，绑定当前 Task，服务端成功后才启动共享循环，因此 RightOverview、ticker 与 FocusPage 消费同一 Session/循环事实。
- 改期的版本冲突会刷新事实并保留弹窗说明；网络中断或超时后前端回读该 Task，只有目标日期已存在且版本前进才确认成功，否则保留错误并要求核对，不把不确定写入伪装成成功。
- Focus 汇总已展示完成 Session 数和分钟数；后端还返回精确秒数。
- 右侧全局概览读取共享的持久化活动 Session、绝对时间快照及本地循环状态，不再用任务状态猜测当前专注对象。
- 通过 `GET /api/v1/stats/inbox` 展示待处理、跟进中、待验收、有阻塞和未读数量；卡片分别跳转 Inbox 全部或 `risk=tracking/blocked/waiting_review` 深链。计数只读取当前可见活动 Inbox 和活动必需 Task，未来 snooze 与归档项不进入口径。
- Sidebar 使用同一统计事实显示待处理徽标，超过 99 显示 `99+`；所有 Inbox 写入会失效同一 Query 前缀，另有 15 秒低频刷新处理 snooze 自然到期。

### 已知缺口

- 任务计划周边界由浏览器本地日期计算，Focus 当日统计使用浏览器 IANA 时区。两者在正常浏览器配置下同属一个用户时区，但服务端尚未接收 IANA 时区来独立计算任务周边界。
- 逾期与本周是多日期聚合，只支持落到具体任务来确定目标日期；它们没有空组级落点。跨日期的改期事务和两个顺序事务不伪装成单个原子操作，排序部分失败时日期保持已确认事实。
- 阻塞、取消需要原因，manual review 需要 Submission/Artifact 验收，解除阻塞/重新打开只适用于 Today 不展示的状态，因此仍由详情页承载。行内编辑入口也刻意复用共享详情，而不是另建字段不完整的编辑器。
- API 已返回 `dueSoon` 和精确专注秒数；今日页尚未展示 `dueSoon`，专注只展示 Session 数和向下取整后的分钟数。
- Today 以四个分页查询组成完整分组；极大数据量下请求次数随页数增长，后续可增加专用聚合端点或虚拟列表，但当前不会静默丢数据。
- 月收入目标、本月收入和客户动态为固定空值；没有真实财务或客户事件来源。

## 目标功能

### 日期与任务计划

- 默认显示用户本地“今天”，支持查看过去或未来日期并一键回到今天。（已交付 T-06B）
- 分组展示逾期、今天、本周稍后；每组规则由服务端按用户时区统一计算。
- 默认优先使用用户保存的 `manual_order`；无手动顺序的任务按优先级、截止时间、创建时间排序。
- 支持组内/跨组拖拽、跨日期安排、空精确日期/未排期落点、恢复默认排序，并对失败写入进行可见回滚或部分成功说明。
- 展示完整结果或分页/渐进加载，不能以固定 100 条作为业务边界。

### 执行与快捷操作

- todo 行 hover/focus 显示“开始执行”；API 仍要求活动负责人，缺失时保留原状态并提示进入详情分派。
- `in_progress + review_policy=none` 显示“完成任务”；manual review 和 waiting_review 不显示该入口，不能绕过验收。
- 活动 Task 显示“开始专注”；已有服务端 Session、本地循环处于 work/break/ready/complete、查询未就绪或任一行内写入进行中时禁用。
- 排序、改期、生命周期和 Focus 创建互斥，防止同一快照同时发出多个版本化命令。

- 在任务行直接开始、完成、编辑、删除和开始专注；受验收约束的任务不得用“快速完成”绕过任务状态命令。（已交付 T-06F/H）
- 点击逾期、临期、待验收等统计可打开对应筛选结果。
- 专注卡绑定真实 Task 与持久化 Focus Session；刷新或重启后提供恢复/结束选择。
- 今日工作台只确认一轮专注完成，不自动把业务任务标记完成。

### 业务概览

- 展示收件箱待处理、跟进中、待验收和阻塞数量，并可直达对应筛选。（已交付）
- 项目模块完成后展示临近项目节点和任务归属。
- 财务/发票 v0.4 完成后，才显示真实月收入、待开票和逾期发票。
- 客户回访 v0.4 完成后，才展示本地回访到期事件；不伪造邮件回复、提案下载等线上活动。

## 关键用户流程

### 晨间安排

1. 用户打开应用，系统按本地日期和 IANA 时区读取今日统计及完整任务集合。
2. 页面分别展示逾期、今天和本周稍后任务。
3. 用户拖拽调整顺序，或把任务安排到另一日期。
4. Sidecar 原子保存排序；若冲突或失败，前端恢复原顺序并提示重试。

### 开始执行

1. 用户从今日任务行选择“开始任务”或“开始专注”。
2. 任务模块校验活动 Assignment 和允许的状态转换。
3. 专注模块创建绑定该任务的 Session；今日页仅展示服务端派生的运行态。
4. Session 停止时，专注模块幂等累计 `actual_minutes`，今日统计随 Query 失效重新读取。

### 处理风险

1. 用户点击逾期、阻塞、待验收或收件箱计数。
2. 应用打开带筛选条件的任务页或收件箱页，并定位来源对象。
3. 用户改期、改派、验收或返工；今日页随后刷新派生数据。

## 数据/API/状态与事件

### 当前事实

- `tasks.planned_date` 保存计划日期，`manual_order` 保存计划组内手动顺序；改变 `planned_date` 时清除原手动顺序。
- `GET /api/v1/tasks` 已支持六个精确状态及派生 `active` 状态、`priority`、`kind`、`project_id`、精确/范围计划日期、`planned_state=scheduled/unscheduled`、截止日期范围、标签、父任务/根任务、`q`、稳定 `sort` 和分页参数。`active` 排除 done/cancelled；`unscheduled` 不得与精确/范围日期混用。
- `PUT /api/v1/tasks/reorder` 已实现：一个请求必须携带目标计划日期组的完整任务 ID/版本集合，原子写入手动顺序或恢复默认；组成员或版本变化时拒绝旧写入。
- `GET /api/v1/stats/today?date=&timezone=` 已实现；任务统计按 `planned_date` 聚合，逾期/临期按 Sidecar 当前 UTC 时间计算。cancelled 不计入总数、剩余、逾期、临期和预计分钟，但其历史实际分钟不会被抹除。
- Focus 统计只读取 `completed` Session 的已关闭正长度 interval，并以 interval 与目标本地日 UTC 边界的实际重叠秒数求和；IANA 时区用当地午夜和下一自然日计算，因此能覆盖跨午夜及夏令时 23/25 小时日。
- Focus `sessions` 是与目标日有正重叠的去重 Session 数，`seconds` 是精确重叠秒数，`minutes=floor(seconds/60)`。paused、cancelled、interrupted、recovery_pending 与开放 interval 都不计入。

### 规划契约

- 任务列表与任务统计后续统一采用用户 IANA 时区；Focus 统计的 IANA 本地日边界已经实现。
- 通过任务列表 API 按日期/范围分页查询，而不是先读取前 100 条再由前端切片。（已交付）
- **已完成按钮基线**：Today 接入现有 `PUT /api/v1/tasks/reorder`，所选精确日期和未排期组支持活动 Task 上移/下移与恢复默认；`TASK_REORDER_SET_CHANGED`、`VERSION_CONFLICT` 和其他失败不会提前改变可见顺序，并触发事实刷新或显示错误。
- **已完成同组拖拽**：拖拽沿用同一完整集合/版本契约，先做可见乐观移动；失败时清除预览并回到刷新后的服务端顺序。
- **已完成明确改期**：单任务沿用批量 `set_planned_date` 事务，版本冲突和模糊响应均刷新事实；同日期跳过写入，任意日期与 null 均可选。
- **已完成跨日期拖拽**：先更新计划日期，再分别重建源/目标组顺序，不把多个日期合成一次 reorder；后续排序失败以部分成功提示呈现，不误报成改期失败。
- **已完成行内管理**：编辑直达共享任务详情；删除使用当前 Task ID/version 和明确二次确认。`VERSION_CONFLICT` 触发事实刷新，`TASK_HAS_ACTIVE_INBOX_RELATIONS` 保留任务并提示先解除活动关系。
- 当前 T-11F 计数直接读取 Inbox 与已关联必需 Task；`task_due`、`task_blocked`、`task_output_submitted` 自动产生 Inbox Item 仍属于 T-11E 来源投影，Today 不自行写 Workflow Event。
- 财务、客户和发票统计只有对应模块交付后才接入；当前 schema 中有表不等于 API/业务已可用。

## 验收标准

- 同一日期下，Today 活动任务组与任务 API 的 `status=active` 口径一致；统计另含当天已完成数和历史实际工时，页面不会把两者误当成同一计数。
- 数据量超过 100 条时，目标日期任务通过自动分页完整访问；无静默截断。（已自动化覆盖通用分页和分组查询边界）
- Focus 统计的用户 IANA 时区、interval 跨午夜、暂停区间、极端时区和夏令时切换已有自动化测试；任务列表的本地日期边界、周日边界与服务端筛选已有前端/Go 定向测试，IANA 参数化任务边界仍待后续增强。
- 按钮式上移/下移或恢复默认成功后刷新顺序保持；写入失败或 `409` 时旧顺序保持并给出可操作提示。（已自动化覆盖活动状态跨状态移动、终态槽位保留和 Today 精确调用）
- 同组拖拽会提交完整活动 ID 顺序，成功后刷新保持；失败/冲突清除乐观顺序并恢复服务端事实。（组件与 hook 已自动化覆盖；真实浏览器指针拖拽和窄屏仍待验收）
- 跨组拖拽落到具体任务时采用其精确日期和相对位置；空所选日期/未排期落点采用组尾。改期失败整体回滚预览；改期成功而任一顺序失败时显示部分成功并以刷新事实为准。（hook 与 Today 组件已自动化覆盖）
- 行内改期只携带当前 Task ID/version，不覆盖其他字段；成功刷新后任务进入目标日期或未排期，版本冲突不自动重试，网络/超时仅在回读证明目标状态后确认成功。（组件与 hook 已自动化覆盖）
- 快捷完成不会绕过 `waiting_review`、manual review 或 Agent 任务的验收规则。
- 行内编辑按钮打开共享详情且不复制另一套编辑事实；行内删除必须二次确认并携带当前版本。版本冲突和活动 Inbox 关系都不会删除 Task，并显示可操作说明。（TaskList、Today 与 hook 已自动化覆盖）
- 专注停止重复提交不会重复累计工时，后台挂起或系统休眠后显示正确。
- 加载、空、错误、重试、窄屏、键盘和拖拽均通过真实浏览器验收。
- 未交付的财务/客户数据明确标记边界，不显示伪造指标。
- 收件箱计数与当前可见活动条目一致；未来 snooze、归档项和可选 Task 不误计为当前阻塞/待验收风险。
