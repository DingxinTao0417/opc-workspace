# 今日工作台模块

> 实现状态截止：2026-08-28；当前数据库 schema v11。
>
> 版本边界：本文同时描述当前实现与目标规划；凡标注“规划”的内容均未在该基线交付。

## 定位与边界

今日工作台是应用的日常入口，负责把“今天要做什么、有什么风险、当前正在专注什么”聚合到一个页面。它是任务、专注、收件箱、项目和后续财务/客户事件的读取视图，不拥有这些模块的第二份业务状态。

- 任务状态、计划日期、排序和工时以任务/专注模块为事实源。
- 收件箱待处理数量和跟进状态从 Inbox Item 与关联任务派生。
- 项目、客户、收入和发票数据由对应模块提供；未实现前必须显示明确空态或“后续版本”，不得填充模拟业务数据。
- 今日页可以发起新建、编辑、排序、专注等操作，但写入仍必须通过各业务模块的 Sidecar API。

## 当前实现状态

当前状态为**部分完成**：真实任务、持久化 Focus Session 和今日统计已经接入，但页面尚不能作为可信的完整日期计划视图。

### 已实现

- `/today` 路由、三栏应用壳、今日标题、当前本地日期和基础统计卡。
- 通过 `GET /api/v1/tasks?page=1&page_size=100` 读取最多 100 条任务。
- 通过 `GET /api/v1/stats/today?date=YYYY-MM-DD&timezone=<IANA>` 读取当天任务总数、完成数、剩余数、逾期/临期数、预估/实际分钟和专注统计；旧调用可继续使用 `timezone_offset_minutes`，未指定时按 UTC。
- 展示预计时长、待完成数和逾期数；任务列表具备加载、空、错误和重试状态，统计查询具备错误与重试提示。
- 可打开新建任务弹窗；任务行状态图标只作展示，点击任务行可打开共享详情弹窗，在受控生命周期区执行开始、阻塞、解除阻塞、完成、取消或重新打开，也可编辑非状态字段或经二次确认删除。
- 今日活跃列表已排除 `done` 和 `cancelled`。统计 API 的当天总数、剩余、逾期、临期和预计分钟排除 cancelled，完成数只统计 done；actual_minutes 保留历史并仍按计划日期累计。
- 任务事实层已提供真实分页、计划日期范围、稳定排序和 `PUT /api/v1/tasks/reorder`。排序命令按完整 `planned_date` 组及每项 `expected_version` 原子校验，并支持 `manual / default`；任务页已经接入按钮式排序，今日页尚未消费。
- Focus 汇总已展示完成 Session 数和分钟数；后端还返回精确秒数。
- 右侧全局概览读取共享的持久化活动 Session、绝对时间快照及本地循环状态，不再用任务状态猜测当前专注对象。

### 已知缺口

- 页面将全部未完成任务按 API 顺序直接切成前 3 条“今天”和第 4–6 条“本周”，没有按 `planned_date` 分组；因此列表可能与按日期聚合的统计互相矛盾。
- 超过 6 条的未完成任务在今日页不展示，超过 100 条的任务根本不会被前端读取。
- 日期 pill 不可切换；任务列表还没有按服务端日期/本周边界或用户时区查询。Focus 当日统计已经支持 IANA 时区。
- 今日页没有拖拽排序、排序持久化入口、失败回滚或恢复默认排序；底层任务 API 与任务页已经具备计划组持久排序和恢复默认能力。
- 任务行仍没有行内编辑、生命周期命令或开始专注等快捷操作；开始、阻塞、完成、取消、重新打开、编辑和删除目前通过详情弹窗完成。
- API 已返回 `dueSoon` 和精确专注秒数；今日页尚未展示 `dueSoon`，专注只展示 Session 数和向下取整后的分钟数。
- 统计查询加载期间没有独立骨架或“读取中”反馈，卡片会暂时显示零值。
- 月收入目标、本月收入和客户动态为固定空值；没有真实财务或客户事件来源。

## 目标功能

### 日期与任务计划

- 默认显示用户本地“今天”，支持查看过去或未来日期并一键回到今天。
- 分组展示逾期、今天、本周稍后；每组规则由服务端按用户时区统一计算。
- 默认优先使用用户保存的 `manual_order`；无手动顺序的任务按优先级、截止时间、创建时间排序。
- 支持组内拖拽、跨日期安排、恢复默认排序，并对失败写入进行可见回滚。
- 展示完整结果或分页/渐进加载，不能以固定 100 条作为业务边界。

### 执行与快捷操作

- 在任务行直接开始、完成、编辑、删除和开始专注；受验收约束的任务不得用“快速完成”绕过任务状态命令。
- 点击逾期、临期、待验收等统计可打开对应筛选结果。
- 专注卡绑定真实 Task 与持久化 Focus Session；刷新或重启后提供恢复/结束选择。
- 今日工作台只确认一轮专注完成，不自动把业务任务标记完成。

### 业务概览

- 展示收件箱待处理、跟进中、待验收和阻塞数量，并可直达对应筛选。
- 项目模块完成后展示临近项目节点和任务归属。
- 财务/发票 v0.4 完成后，才显示真实月收入、待开票和逾期发票。
- 客户回访 v0.4 完成后，才展示本地回访到期事件；不伪造邮件回复、提案下载等线上活动。

## 关键用户流程

### 晨间安排

1. 用户打开应用，系统按本地日期和 IANA 时区读取今日统计及完整任务集合。
2. 页面分别展示逾期、今天和本周稍后任务。
3. 用户拖拽调整顺序，或把任务安排到另一日期。
4. Sidecar 原子保存排序；若冲突或失败，前端恢复原顺序并提示重试。

### 开始执行

1. 用户从今日任务行选择“开始任务”或“开始专注”。
2. 任务模块校验活动 Assignment 和允许的状态转换。
3. 专注模块创建绑定该任务的 Session；今日页仅展示服务端派生的运行态。
4. Session 停止时，专注模块幂等累计 `actual_minutes`，今日统计随 Query 失效重新读取。

### 处理风险

1. 用户点击逾期、阻塞、待验收或收件箱计数。
2. 应用打开带筛选条件的任务页或收件箱页，并定位来源对象。
3. 用户改期、改派、验收或返工；今日页随后刷新派生数据。

## 数据/API/状态与事件

### 当前事实

- `tasks.planned_date` 保存计划日期，`manual_order` 保存计划组内手动顺序；改变 `planned_date` 时清除原手动顺序。
- `GET /api/v1/tasks` 已支持六状态、`priority`、`kind`、`project_id`、精确/范围计划日期、截止日期范围、标签、父任务/根任务、`q`、稳定 `sort` 和分页参数，但今日页仍只读取第一页并在前端切片。
- `PUT /api/v1/tasks/reorder` 已实现：一个请求必须携带目标计划日期组的完整任务 ID/版本集合，原子写入手动顺序或恢复默认；组成员或版本变化时拒绝旧写入。
- `GET /api/v1/stats/today?date=&timezone=` 已实现；任务统计按 `planned_date` 聚合，逾期/临期按 Sidecar 当前 UTC 时间计算。cancelled 不计入总数、剩余、逾期、临期和预计分钟，但其历史实际分钟不会被抹除。
- Focus 统计只读取 `completed` Session 的已关闭正长度 interval，并以 interval 与目标本地日 UTC 边界的实际重叠秒数求和；IANA 时区用当地午夜和下一自然日计算，因此能覆盖跨午夜及夏令时 23/25 小时日。
- Focus `sessions` 是与目标日有正重叠的去重 Session 数，`seconds` 是精确重叠秒数，`minutes=floor(seconds/60)`。paused、cancelled、interrupted、recovery_pending 与开放 interval 都不计入。

### 规划契约

- 任务列表与任务统计后续统一采用用户 IANA 时区；Focus 统计的 IANA 本地日边界已经实现。
- 通过任务列表 API 按日期/范围分页查询，而不是先读取前 100 条再由前端切片。
- 今日页接入现有 `PUT /api/v1/tasks/reorder`，并在拖拽失败、`TASK_REORDER_SET_CHANGED` 或 `VERSION_CONFLICT` 时回滚可见顺序并刷新任务组。
- 今日页消费 `task_due`、`task_blocked`、`task_output_submitted`、`reminder_due` 等本地事件的派生计数，但不自行写 Workflow Event。
- 财务、客户和发票统计只有对应模块交付后才接入；当前 schema 中有表不等于 API/业务已可用。

## 与其他模块协作

| 模块      | 今日工作台读取                          | 今日工作台发起                   | 事实归属      |
| --------- | --------------------------------------- | -------------------------------- | ------------- |
| 任务      | 日期、状态、优先级、预估/实际工时、排序 | 新建、编辑、状态命令、改期、排序 | 任务模块      |
| 专注      | 活动 Session、剩余时间、当日统计        | 选择任务并开始/暂停/停止         | 专注模块      |
| 收件箱    | 待处理、跟进、待验收、阻塞计数          | 打开筛选或处理详情               | 收件箱模块    |
| 项目      | 项目名、临近节点、派生进度              | 跳转项目详情                     | 项目模块      |
| 客户      | 本地客户活动、后续回访提醒              | 跳转客户详情                     | 客户模块      |
| 财务/发票 | 真实月收入、待开票/逾期                 | 跳转对应工作项                   | 财务/发票模块 |

总体依赖与事件流参见[整体功能架构](../functional-architecture.md)。

## 分阶段实施

1. **v0.1 数据一致性**：服务端日期/时区查询、完整分页、真实分组，确保列表与统计使用同一口径。
2. **v0.1 计划交互**：拖拽排序、恢复默认、改期、编辑/删除/专注快捷操作及失败回滚。
3. **v0.1 本地编排接入**：展示收件箱、阻塞、待验收等派生计数和详情跳转。
4. **v0.1 专注闭环（已完成）**：绑定持久化 Session，按精确秒数累计完整分钟，并支持心跳、刷新恢复和崩溃恢复。
5. **后续模块接入**：仅在项目、客户回访、财务和发票各自交付后增加真实概览；不以占位数据提前宣称完成。

## 验收标准

- 同一日期下，今日列表数量、完成数、预估/实际时长与统计 API 一致。
- 数据量超过 100 条时，目标日期任务仍可完整访问；无静默截断。
- Focus 统计的用户 IANA 时区、interval 跨午夜、暂停区间、极端时区和夏令时切换已有自动化测试；任务列表的同口径日期计划仍待完成。
- 拖拽后刷新顺序保持；写入失败或 `409` 时恢复旧顺序并给出可操作提示。
- 快捷完成不会绕过 `waiting_review`、manual review 或 Agent 任务的验收规则。
- 专注停止重复提交不会重复累计工时，后台挂起或系统休眠后显示正确。
- 加载、空、错误、重试、窄屏、键盘和拖拽均通过真实浏览器验收。
- 未交付的财务/客户数据明确标记边界，不显示伪造指标。
