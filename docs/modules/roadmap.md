# 路线图模块

> 目标版本：v0.3。该模块是本地季度规划和里程碑视图，不属于 v0.1。当前已完成 R2 数据/API（schema v36）、R3 基础界面、R4 同季度排序/跨年多季度移动/季度内精确日期调整，以及 R5 本地到期/达成 Inbox 事件。

## 定位与边界

路线图用于把长期目标、季度里程碑与项目/任务事实关联起来，回答“接下来要达成什么、何时达成、由哪些工作支撑”。它不是第二套项目管理器，也不复制项目或任务的完成百分比。

- 数据、计算和提醒全部在本机完成。
- 里程碑进度只从关联项目和任务派生，不接受多个可写进度事实源。
- 里程碑临期或达成可创建本地 Inbox Item，但不自动改变项目或任务状态。
- 不发布公开路线图、不同步外部项目工具，也不自动对外发送任何内容。

## 当前实现状态

- `/roadmap` 已替换为真实季度视图：可切换年份、Q1–Q4、状态和关联 Project，Project 筛选器支持服务端搜索与自身分页；路线图列表每页 20 条，显示完整服务端总数、范围、前后翻页和后台刷新状态，筛选变化回到第一页，服务端总数收缩时夹回有效末页。页面展示真实里程碑、关联 Project 深链和只读派生 Task 完成度；具备加载、空、错误重试和不使用 demo 数据的提示。
- schema v36 的 `roadmap_milestones` 与 `roadmap_milestone_projects` 保存标题、说明、明确年份/季度、同季度目标日期、状态、排序、归档来源、乐观版本及项目关联；项目删除被关联表外键阻止，删除里程碑会清理其关联。迁移不创建 demo 数据。
- 已交付本地鉴权 API：`GET/POST /api/v1/roadmap/milestones`、`GET/PATCH/DELETE /api/v1/roadmap/milestones/:id`、`PUT /api/v1/roadmap/milestones/reorder`、归档/恢复端点。列表支持 year/quarter/status/project/归档筛选和分页；创建、编辑、项目关联、归档恢复与重排都由 Sidecar 校验，编辑/归档/恢复/删除使用 `If-Match`，重排的每项使用 `expected_version` 并在一个事务提交。响应只从关联 Project/Task 读取项目摘要及任务完成度，不写入第二份进度。
- 列表另支持白名单 `sort=target_date`，按纯日期升序并以 ID 作为稳定后备键；非法排序返回 `INVALID_FILTER`，默认季度手工顺序不变。Today 右侧分别读取 planned/active 各前 3 条并再次按日期/ID 合并，只展示最近 3 条和派生 Project/Task 归属，具备加载、空、聚合失败重试与路线图入口。
- 当前界面可创建当前季度里程碑、选择最多 100 个已读取的非归档 Project 关联，并直接归档或恢复；非归档里程碑可编辑标题、说明、年份、季度、目标日期、状态和项目关联，所有写入携带当前 `version`。永久删除只在归档视图提供，必须先打开确认弹窗再提交，Sidecar 继续强制 `confirm=true`、`If-Match` 和“仅已归档可删”。卡片或直接 URL `?milestone=<id>` 可按 ID 读取最新详情，展示完整说明、派生任务进度、Project 深链、期间、版本和审计时间；关闭或进入编辑只删除 `milestone` 并保留其他查询参数，加载、错误重试、归档只读提示及用详情最新版本进入编辑均已接通。
- 同季度顺序调整已接入界面：只在“未归档全部状态、无 Project 筛选、本季度 2–100 条”时开放；进入后强制读取第 1 页、`page_size=100` 的完整季度集合，隐藏分页并冻结筛选/新增/卡片写操作。用户可拖动卡片或使用有明确名称的上移/下移按钮预览顺序，保存时提交所有 `{id, expected_version}`；Sidecar 在单事务中校验同季度、非归档和版本后重写 `manual_order`。失败不修改已查询事实，界面恢复服务端顺序并提示重试；超过 API 100 条上限时明确禁用，避免局部分页重排破坏隐藏条目。
- PATCH 调整 `year` 或 `quarter` 时，Sidecar 在同一事务读取目标季度当前最大 `manual_order`，把里程碑追加到目标季度尾部并递增版本；源季度不留副本，避免沿用旧季度序号与目标季度现有条目碰撞。此规则同时服务年度跨季度移动和现有编辑表单的季度调整。
- 页面可切换“季度视图 / 年度视图”；年度视图按历史原型的 Q1–Q4 分区展示真实里程碑，年度列表使用 `page_size=100`。在未归档、无 Project 筛选且年度总量不超过 100 条时，可进入“调整季度”：拖动卡片到目标季度或年度首尾落点，或使用上一季度/下一季度按钮；Q1 向前移动到上一年 Q4，Q4 向后移动到下一年 Q1。所有操作都通过 PATCH 携带当前版本，并把目标日期明确设为目标季度末。写入期间禁用重复移动，失败保留/刷新服务端事实并显示错误；超过容量时不开放局部年度拖拽。
- 季度视图在未归档、无 Project 筛选且完整季度集合不超过 100 条时可进入“调整日期”：页面读取 `page_size=100` 的完整集合并冻结筛选、新建和分页，展示季度三个月的星期对齐日历；卡片可拖到任一具体日期，也可用卡片内原生日期输入作为键盘替代。每次调整立即 PATCH `target_date + expected_version`，成功刷新当前事实，失败清除拖拽态、保留原日期并重新读取服务端；超过容量时不开放局部分页日期调整。
- schema v39 已接入 `roadmap_milestone` Inbox 来源：`planned/active` 里程碑在 Sidecar 本地日历日达到 `target_date` 后，由启动补偿和与 Reminder 共用的周期扫描生成 P1 到期事件；状态首次转为 `achieved` 时在原写事务生成 P2 达成事件。事件键为 `roadmap:<milestone-id>:<due|achieved>:<milestone-version>`；到期扫描还按里程碑 ID + `target_date` 检查历史来源，排序或标题编辑递增版本后不会重复提醒同一计划日期。改期或状态离开当前事件语义会自动解决活动来源，归档会终结来源，永久删除前把全部终态来源标记 `source_deleted_at` 并保留快照。Inbox 详情显示目标日期、季度、计划版本和路线图入口。
- 当前 R5 使用 Inbox Item 表达本地提醒事实，并复用 Reminder 扫描器的生命周期，不额外创建 `reminders` 行，也没有系统原生通知；原生通知仍未交付。创建/编辑表单的多项目选择仍是单页 100 个项目，不等于已交付大数据量多选器。
- 历史路线图视觉原型已移除，后续以当前 React 占位实现、本文和 PRD 为准。
- 现有项目 API 和完整任务事实层也尚未完成，是本模块的前置依赖。

## 目标功能

- 按年和季度分组显示里程碑，支持切换期间和归档视图。
- 新建、编辑、调整目标日期、改变状态和归档里程碑。
- 关联一个或多个项目，并从项目/任务状态派生进度和风险提示。
- 支持拖拽调整季度或日期；服务端失败时恢复原位置并给出可重试错误。
- 从里程碑跳转项目、任务和相关 Inbox Item。
- 临期、逾期、阻塞或达成时产生幂等的本地事件和提醒。

## 关键用户流程

1. **创建里程碑**：用户选择季度，填写标题、目标日期、说明、状态和关联项目。
2. **查看季度计划**：页面按用户本地时区分组，展示派生进度、剩余时间和风险。
3. **调整排期**：可在完整同季度集合内拖拽卡片或用键盘可达按钮调整顺序并显式原子保存；季度视图可把卡片拖到三个月日历的具体日期或用日期输入立即保存；年度视图可拖到 Q1–Q4/年度首尾落点，或用上一/下一季度按钮跨年连续移动。冲突或失败时恢复服务端事实并提示重试。
4. **检查进度**：进入里程碑详情查看关联项目、任务完成情况和阻塞项，不编辑复制的百分比。
5. **达成与归档**：用户明确确认里程碑达成或归档；路线图只追加自身事件和读取关联 Task 结果，不直接完成或验收 Task。若仍有必需 Task，owner 必须在任务模块分别执行受控命令；Inbox Item 继续按 resolution_policy 派生解决。
6. **到期提醒**：Sidecar 以操作系统本地日历日解释纯日期，启动及周期补偿生成去重 Inbox Item；用户决定拆任务、稍后、解决或忽略。

## 数据、API、状态与事件

### 数据

- 新增 `roadmap_milestones`：`id`、标题、说明、季度、目标日期、状态、排序、版本及审计时间。
- 使用关联表 `roadmap_milestone_projects` 支持多项目关联，并设置唯一组合约束。
- 进度、已完成任务数和风险为查询派生值，不持久化为可独立编辑字段。
- 纯日期使用 `YYYY-MM-DD` 并按用户本地时区解释；季度由明确的年份与季度字段表示。

### API（R2 已交付）

- `GET / POST /api/v1/roadmap/milestones`
- `GET / PATCH / DELETE /api/v1/roadmap/milestones/:id`
- `PUT /api/v1/roadmap/milestones/reorder`
- `POST /api/v1/roadmap/milestones/:id/archive`
- `POST /api/v1/roadmap/milestones/:id/restore`

列表支持年份、季度、状态、项目和归档筛选；可选 `sort=target_date` 提供跨季度目标日期稳定升序，其他值拒绝，缺省时保留季度手工顺序。重排必须作为单事务保存并检查 `expected_version`。PATCH 跨年或跨季度时必须把 `manual_order` 原子重置为目标季度尾部，不能沿用源季度顺序。

### 状态与事件

- 建议状态：`planned / active / achieved / archived`；上线前由迁移和状态机测试固化。
- 逾期和风险优先根据日期、关联项目和阻塞任务派生，不另建可漂移状态。
- 事件示例：`roadmap_milestone.created`、`roadmap_milestone.rescheduled`、`roadmap_milestone.due`、`roadmap_milestone.achieved`、`roadmap_milestone.archived`。
- Inbox 事件使用里程碑 ID、事件类型和计划版本构成唯一事件键；到期补扫另按同一目标日期判重，避免无关版本增长重复提醒。

## 与其他模块协作

- **项目**：项目是交付事实源；项目删除时应阻止、解除关联或保留可解释快照，不能悄悄删除里程碑。
- **任务**：任务状态和阻塞信息参与进度派生；路线图不直接批量改任务状态。
- **今日/收件箱**：临期、逾期和阻塞只生成本地提示与待办。
- **今日右侧概览**：只读 planned/active 最早节点及 Roadmap 已派生的 Project/Task 摘要；不写第二份进度，每条以 `?milestone=<id>` 直达指定详情。
- **内容日历**：可共享季度筛选和项目关联，但内容条目与里程碑保持独立生命周期。
- **自动化**：消费本地里程碑事件并创建 Inbox Item、Task 或 Reminder，不对外发送。

## 分阶段实施

1. **R1 前置依赖**：完成项目 CRUD、任务关联和稳定的项目派生进度口径。
2. **R2 数据/API（已完成）**：新增里程碑及关联迁移，实现 CRUD、筛选、状态、项目关联、派生 Task 完成度及并发测试。
3. **R3 基础界面（已完成）**：已交付季度/状态/Project 浏览、稳定分页、新建、完整基础事实编辑、按 ID 详情、Project 跳转、归档恢复、保护性永久删除及加载/刷新/空/错误状态。
4. **R4 排期交互（已完成）**：完整同季度集合的卡片拖拽/批量重排、年度 Q1–Q4 时间线、跨季度与跨年度拖拽、季度三月日历精确日期拖拽、失败恢复和键盘替代已交付。
5. **R5 本地事件（已完成）**：schema v39 接入到期/达成 Inbox 来源、启动与周期调度补偿、稳定去重、变更终结、删除协调和前端来源快照。当前“提醒”由 Inbox Item 承载，不创建独立 Reminder occurrence，原生通知仍待后续。
6. **Today 概览联动（已完成）**：列表目标日期排序、planned/active 两路有界读取、稳定合并、Project/Task 归属、加载/空/失败状态及 `?milestone=<id>` 指定详情深链已交付。

## 验收标准

- 年/季度边界、跨年和用户时区的日期分组正确。
- 进度完全从关联项目/任务派生，数据库不存在可独立漂移的第二份百分比。
- 项目关联、解除关联和删除约束可解释，历史事件可追踪。
- 同季度顺序保存必须覆盖当前完整集合；拖拽预览、编辑和重排失败时恢复服务端事实，并发旧写入返回冲突。超过 100 条时不得降级为当前分页局部保存。
- 临期/达成事件重扫不重复，且不会自动改变项目状态。
- 页面具备加载、空、错误、重试、归档与恢复状态，并完成真实浏览器拖拽和键盘验收。
- `sort=target_date` 在分页前按目标日期/ID 稳定排序；Today 合并两种状态后仍取全局最早 3 条，任一路失败不得把另一半误装成完整结果。
- 直接打开 `?milestone=<id>` 会读取该 ID 最新详情；关闭与进入编辑删除该参数但保留其他查询上下文，列表卡片和 Today 入口共享同一 URL 契约。
- 断网完整可用，不存在公开发布、云同步或自动外发路径。
